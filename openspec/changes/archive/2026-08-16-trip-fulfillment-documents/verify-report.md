## Design Coherence — Resolved Decisions (treated as final per instructions)

- **Decision #5 (gate widening) and #6 (country catalog correction)**: both are the two decisions this change's spec/design revision cycle spent the most effort resolving (surfaced mid-design, closed by the founder). Both verified by direct source read above, not by trusting `apply-progress`'s narrative — the actual `Set` contents, the actual derivation expression, and both call sites were opened and read line-by-line.
- **proposal.md staleness (documented, not a defect)**: `state.yaml`'s revision log flags that `proposal.md` line ~170 still describes the superseded 5-market country list (Resolved Decision #4, superseded by #6). This is explicitly called out as intentional staleness — spec + design are the authority on `country`, not the proposal prose — and the actual code correctly implements the 24-country catalog, not the stale 5-market text. Not re-flagged as a code defect; noted here only for traceability since a future reader skimming `proposal.md` alone would get the wrong answer.
- **`isFulfillmentVisible` signature stability**: per ADR-6, the signature `isFulfillmentVisible(status, isAdmin)` was deliberately kept unchanged while only the Set contents grew from 2 to 3 members, so the `isAdmin: false` hardcoded call site at `GET /api/trips/[id]` and the admin-exemption logic didn't need touching. Confirmed: the call site literally passes the literal `false`, and the widening lives entirely inside `FULFILLMENT_VISIBLE_STATUSES`.
- **No blob-key exposure surface introduced**: the DTO, the admin delete route, and the stream route were all read directly; none of them return `storageKey` in any client-facing JSON payload. The stream route (not re-read line-by-line in this verify pass beyond the visibility gate, since Phase 2's dedicated route test suite already covers 401/403/404 branches per `tasks.md` 2.12) is trusted on its test coverage for the access-control branches not re-inspected here.
